# USB OTG → USJ handoff: bounded detach candidate

Scope: source review and deterministic host execution only. No hardware reads/writes, target build, flash, or commit by this worker. Existing 3dc firmware evidence was preserved.

The observed BLE journal `docs/audit/artifacts/usb_otg_ble_priority_20261114/cdc-migration-rom-01.ble-control.jsonl` contains RACK at monotonic94767.596581305, RAPP at94767.641666585, then disconnect at94771.649426564. RAPP is published before the main task's bounded publication delay and before PrepareRestart; it is not evidence that the owner acknowledged quiescence or that ROM enumerated. Parent separately observed unchanged303a:4041/devnum11 beyond238seconds and zero bytes during a20second old-CDC read; those observations do not locate CPU execution or prove chip death.

Confirmed code gap: original OwnerQuiesce called TinyUSB disconnect, reset OTG and immediately restored the internal PHY to USJ without a minimum detached interval. TinyUSB0.21's real DWC2 implementation (`managed_components/espressif__tinyusb/src/portable/synopsys/dwc2/dcd_dwc2.c`, dcd_disconnect) asserts USB_WRAP pull override with D+/D- pulldowns and SDIS. The immediately following USJ HAL selects the internal PHY and enables its pads; disabling USJ pull override resumes its normal pull behavior. A too-short disconnect is a plausible explanation for retained host enumeration, but is not a proven field cause without bus/host transition evidence.

Excluded unsupported explanations: IDF5.5.5 `usb_serial_jtag_ll_phy_enable_external(false)` really sets RTC software PHY selection toUSJ; it is not merely a controller-local bit. ESP32-S3 TRM1.7 §8.3,p536 expressly supports FORCE_DOWNLOAD_BOOT plus CPU reset. Normal IDF `esp_system_reset_modules_on_exit()` writes PERIP_RST_EN0=0 before CPU restart, so the OTG held-reset bit is not necessarily left asserted forever. No change to reset type, ROM flag policy, watchdog or DMA-stop proof is justified by the available record.

The candidate changes only OwnerQuiesce: first owner call masks its installed IRQ, calls tud_disconnect once, stores monotonic time and returns; subsequent calls return until20ms has elapsed. Only then does the original persist-clear → OTG module-reset/readback → USJ-PHY selection → release-ACK chain execute. A separate boolean supports a real timestamp0. No internal polling loop, allocation, task deletion or buffer reuse was added. The existing SerialIo wait/checkpoint yields while waiting; PrepareRestart's existing absolute250ms includes this phase. Timeout still retains all state and follows the existing controlled fallback. During the gap, DMA is explicitly still potentially active, and the emergency wrapper follows its existing Core Reset path.

20ms is an engineering margin, not a USB-prescribed20ms threshold or measured electrical guarantee. USB2.0 §7.1.7.3 and §11.5.2.2 describe disconnect detection of sustained SE0; the intended next HIL must record removal/addition, changed device number and actual ROM303a:1001, independently of BLE disconnect. A host that never sees a valid detach can retain old descriptor/address state.
