# ADS continuous/pulse diagnostic implementation — 2026-11-16

This is a new bounded diagnostic, not a change to the matrix sampling mode, startup speed scan, CRC acceptance, rail calibration or scientific validity rules. Hardware execution is **NOT_RUN by this worker**; root owns build/flash/capture.

The new `sensorarrayAdsGapRunTimingProbe` obtains the existing CHECK owner at a complete-frame boundary. Admission requires a stable physical snapshot, RESET clear, internal reference off, VBIAS already on, AVDD/AVSS reference, CRC8+STATUS, continuous saved mode and START observed low. Main additionally checks known CAP/VOLT routing and all frontend owners. Unsupported admission does not perform configuration writes. A genuine register/shadow/reset/owner fault remains distinguishable from an unchanged rejection.

`sensorarrayAdsTimingProbeRun` collects 200 primary attempts in each of CONT/PULSE × PGA1/bypass. It preserves the selected SPI clock and all POWER/reference/route/calibration settings. MODE0 is 00h or40h, MODE1 is00h, MODE2 is0Fh or8Fh, and both mux inputs select AINCOM (AAh). At38400SPS the effective filter is first-stage SINC5. It neither calls matrix encoders nor trains PGA/value caches.

Every primary read uses the actual driver FreshChecked path with zero CRC retry budget. Pulse START1 is unconditional in the existing driver. The post-START `configuredDrdyGeneration` is the read floor. If a falling edge was already absorbed into that software fence, the attempt is `start_fence_missed` and the diagnostic is incomplete; the code does not assume that a14.5µs opcode guarantees return before a207µs conversion. It also accepts an edge occurring after the fence but before the caller resumes. Config-generation changes remain hard faults even when the read returned the earlier CRC error.

Each completed pulse primary read is followed by one explicitly nonfresh `held_repeat`. The held read must have no new generation, CRC-valid NEW_DATA=0, and the same raw value if the primary value was valid. Its CRC counts are separate from primary attempts. It never becomes a scientific sample. Both CRC bit directions are counted; original bad packets come from the driver's rejected-packet evidence. Good raw/status values have `wireKnown=0` and unknown CRC-byte text because the API does not supply their original checksum bytes; parity counters remain observable. At most8 selected records per group are retained, with explicit omitted-category counts.

The2s absolute deadline reserves the final500ms for cleanup. Reads, writes, verification and DRDY use the shared work deadline; there is no renewed sample budget. One real RTOS tick is yielded after every32 attempts. Cleanup first writes and verifies MODE0 continuous, then sends STOP1, then performs the existing complete register/shadow restore. This is required because STOP1 cannot cancel an in-progress pulse. Restore is verified against saved physical registers and SPI clock. Unknown DMA completion prevents all further SPI/restore/reuse and retains the persistent descriptor. Original, terminal and cleanup errors are separate. The existing helper transaction generation invalidates profile/value caches and enables the next-frame settling guard without resetting frame count, health schedule or failure budgets.

Execution completion, CRC rate, parity coverage and restore verification are separate. `completed=1` may still have firstError=CRC and a group rate above2.5%; the diagnostic reports that evidence and does not select a new clock. The user's discussion of5% did not change boot qualification or allow any bad scientific sample. Software observation times are not hardware edge timestamps. An AA timing comparison does not reproduce external matrix loading or prove the physical final-bit root cause.
