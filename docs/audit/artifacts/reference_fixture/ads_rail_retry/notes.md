# MIXED rail CRC first-error and bounded retry follow-up

The real `rail-fixed-mixed8-01.rx.bin` capture is preserved separately. It reports successful rail transaction 35 at seq4044, then transaction 36 at seq4145 failing its fifth logical monitor read with `err=0x109`, `restored=1`, `cleanup=0`. Its duration was 57,355 us, within the existing 250,000 us owner deadline. This is a CRC failure, not evidence of a failed restore or an expired transaction timeout.

At seq4145 the prior monitor sample is 101 frames old. `CONFIG_SENSORARRAY_ADS_MATRIX_RAIL_MAX_AGE_FRAMES=100` correctly rejects that value. The longer last-good diagnostic age does not make it a valid matrix reference. This patch does not extend any age limit or advance last-good time/frame on failure.

Two confirmed software defects are addressed:

1. `sensorarrayAdsMatrixGetRail` returned bool, discarding the refresh's `ESP_ERR_INVALID_CRC`. `sensorarrayAdsMatrixEngineReadFrame` then captured and returned the hardcoded `ESP_ERR_INVALID_STATE`, which MIXED and main faithfully reported as 0x103. GetRail now returns `esp_err_t`; the frame failure branch captures and returns that original error. Cleanup comes only from a newly started rail transaction, with its first cleanup error taking precedence over a later SAFE error. An old transaction's cleanup is never attached to a failed owner admission. The register ID is 255 (not applicable), not a fabricated register zero comparison.
2. Rail monitor reads used a single un-retried conversion. New private `sensorarrayAdsReadRailFreshAdc1` uses the existing production `ads126xAdcReadAdc1FreshChecked` and shares one CRC retry across the complete monitor transaction. It does not restart or extend the 250 ms owner deadline. A bad wire frame cannot consume one of the four settling discards or the final accepted sample. The retry waits for a newer DRDY generation and verifies the configuration generation and NEW_DATA. CRC, PGA/reference/reset alarm rejection and restoration are unchanged. Exhaustion returns the first CRC error even if the retry subsequently times out; terminal error remains separately observable.

`RAILSAMPLE` retains `n` as the number of logical read calls and adds `accepted`, `crcErrors`, `crcRetries` and `terminalError`. Accepted counts only CRC/freshness/status-valid conversions. A recovered CRC is still counted. `RAILCRC` records the first rejected wire bytes and their received/computed CRC, physical generation, DRDY generation and timestamp. The records are emitted after the transaction ends and the owner is released. Failed bytes never enter the returned rail value or cache.

The acquisition plan's new `auxiliaryTransactionsAllowed` flag is owned by the coordinated MIXED boundary patch. Matrix uses it to reject a missing/expired rail without running a helper inside a mixed segment. That patch prepares rail before the first mode group and sets the flag false for child groups. It is intentionally separate from these ADS changes. No main/mixed source or driver was edited by this follow-up; the parent separately owns the RDATA/NOP experiment.

Executed regressions and source hashes are in `host_test_manifest.json`:

- Rail profile/save/restore plus the actual production fresh-read driver: 33 cases pass. New cases cover bad-to-good, final sample bad-to-good, one budget across multiple discards, consecutive bad frames, CRC followed by DRDY timeout, owner deadline exhaustion, unchanged output on error, and first CRC evidence retention. The existing restore-failure cases still pass.
- Actual GetRail plus the exact production frame rail-failure branch: 11 cases pass. They cover 0x109 preservation, restore/SAFE error ordering, old transaction evidence, age100/101, successful refresh, nominal refresh success without a usable value, VOLT prohibition, mixed child prohibition, and transaction counter wrap.
- Battery snapshot evidence (9), fault formatter fixtures (11), matrix diagnostic formatter, measurement logic, and `git diff --check` pass.

Fixtures are synthetic. The rail tests execute real production control flow with a fake register bank and bounded DRDY/SPI outcomes; the existing driver harness separately covers persistent DMA descriptor lifetime and quarantine. Host PASS is not a claim that the physical ADC CRC corruption is fixed. Subsequent build, hardware capture and performance evidence belong to the parent integration run.

The final coordinated boundary patch adds public `sensorarrayAdsMatrixEngineRecordMixedBoundaryFault` (new in this round). A failure before the first MIXED child group gets a current-sequence RAIL_MONITOR context with mode MIXED, route unknown, owner RAIL, register 255, and attempted/acquired false. Prior-sequence evidence is cleared; repeated current-sequence reports preserve the first original error and first cleanup error. `CC=/usr/bin/gcc python3 tools/test_mixed_rail_boundary.py` was actually executed after integration: all 14 cases pass, including the actual context helper, complete production MIXED module and actual fault formatter. The 33 rail cases and 11 error-chain cases were also rerun successfully after this addition. Parent final-build manifests supersede the earlier host manifest's source hash for this narrow addition.
