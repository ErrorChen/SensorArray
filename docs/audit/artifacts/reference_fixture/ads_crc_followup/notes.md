# ADC CRC follow-up after the real RES8 run

This follow-up preserves the raw capture `../repaired-res8-01.rx.bin`. Its seq 4231 records `ESP_ERR_INVALID_CRC` (0x109), attempts=64, spi=1 and fresh mask FFFFFFFFFFFFFFFE. This identifies one conversion read failure at S1D1; the other 63 cells had fresh conversions. It is not a periodic-register-health fault and does not demonstrate 64 SPI failures. The pre-cleanup mode/route was lost in the old MATRIX_ROUTE/NONE/SAFE diagnostic.

The verified software defect was that `sensorarrayAdsMatrixMeasureCellImpl` retried TIMEOUT and INVALID_RESPONSE but omitted the CRC error newly enabled on the production path. The actual electrical or timing cause of the rejected bytes is not established by that capture: it did not record them. The CRC polynomial remains 0x107 (four ADC1 data bytes, zero-padded polynomial division); STATUS is outside CRC coverage. Datasheet §9.4.7.2 says RDATA1 retrieves the holding register without requiring read-start synchronization to DRDY. The 2 MHz SPI read length alone is therefore not proof of data tearing at 38.4 ksps. SPI mode 1, CRC configuration, thresholds and sampling rate were retained.

## Production changes

- `ads126xAdcReadAdc1FreshChecked` is a new interface. Its caller must already own the transaction deadline. Matrix cells retain the existing 100 ms total budget, including configuration, every DRDY wait, SPI operation, autorange and retry. The shared CRC budget is initialized once per cell from `CONFIG_SENSORARRAY_ADS_MATRIX_IO_RETRY_COUNT` (currently 1), and is not reset by adaptive or high-Z reads in that cell. A retry waits beyond the DRDY generation observed after the rejected read. Raw/status outputs change only after a CRC-valid, fresh result with the unchanged physical configuration generation.
- A failed retry returns the first error, with the final retry error separately recorded. A DMA completion timeout retains its persistent descriptor/buffers and quarantines ADS. The matrix exits both acquisition loops without routing another row when quarantined. A later row-route failure cannot overwrite an earlier cell error.
- Rejected ADC1 wire bytes, length, received/computed CRC, configured CRC/status mode, physical/DRDY generations and monotonic microsecond timestamp are copied into bounded evidence. No rejected raw code is offered to PGA selection or the value cache. The cumulative ADC1 CRC error counter covers every driver ADC1 CRC rejection; the retry counter counts fresh-read retry attempts from this new interface, including an attempt whose DRDY wait subsequently times out. These are device-boot counters, not host delivery counts.
- `ADSSPI` reports per-frame CRC failures/retries/recovered reads, cumulative counters, the first rejected S/D, and separate terminal/frame errors. `ADSSPIBYTES` records the first rejected wire frame. Bytes are the status/data/check byte sequence after RDATA1, in wire order; use `len` and `statusEnabled` to interpret the fixed six-byte hex storage. Recovered text is limited to once per second; an unrecovered CRC is always queued. Counts and Xhh semantics are not rate limited. Diagnostics enter the existing bounded event queue, so text is not guaranteed to reach the host.
- Failed cell context is captured before cleanup, including frame sequence and the precise MATRIX_CRC/MATRIX_READ/MATRIX_DRDY/RESET stage. `ADSFAULTREG reg=255` means no register applies to sample failures. MATRIX_CRC expected/actual are computed/received CRC bytes, not register values. S/D is reported separately in ADSSPI. The original failure remains fatal when the existing all-invalid policy requires SAFE; no unsafe error was downgraded.
- `ADSHEALTH` is queued after each due health transaction ends, with sequence, cumulative engine frame count, mode-entry count, interval, precision flag and original result. This permits HIL evidence for actual 128/256/384/512 engine boundaries rather than guessing from host sequence.
- `sensorarrayAdsMathConfirmOpenSet` now computes the actual median before its early HIGH_Z return. The prior branch replaced the diagnostic node voltage with zero. OPEN thresholds and acceptance semantics are unchanged. This does not explain or repair the S8D8 fixture result by itself.

## Executed verification

Exact commands, exit codes, source hashes and HEAD are in `host_test_manifest.json`; logs are adjacent. All four commands passed:

1. Production driver fault injection: owner required; CRC then a distinct DRDY/new valid frame; shared budget across multiple reads; persistent CRC exhaustion; CRC followed by DRDY timeout; CRC followed by DMA completion timeout and no further queue/reuse; physical configuration change; missing NEW_DATA; generation wrap; existing reference, CRC bit-corruption, register and DMA lifetime cases.
2. Production measurement logic, including early HIGH_Z diagnostic median and stage names.
3. Eleven synthetic fault replays generated by the actual C formatter, including pre-cleanup MATRIX_CRC with distinct original/cleanup errors. These are not repaired field logs.
4. Actual production ADSSPI logging function executed with a bounded synthetic event sink: maximum tested record 219 bytes, recovered-rate limiting, unrecovered error bypass and byte/counter semantics. This test checks diagnostic formatting, not hardware timing.

The new driver deadline test allows the already existing FreeRTOS wait quantization of at most one tick beyond the absolute deadline; it verifies that retry does not renew the owner budget. The whole matrix loop's conditional first-error preservation and quarantine exit were reviewed, not claimed as an independently executed full matrix timeout HIL test. Build, flash and physical follow-up remain owned by the root task, which is the sole serial reader. This agent performed no serial or physical operation.
